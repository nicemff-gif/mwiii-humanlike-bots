# 人工测试 01：多人 TDM 加载、感知与记忆

这份测试现在需要人工执行。优先完成 A 组，约 5 分钟；A 组通过后再做 B 组，约 10–15 分钟。C 组可以随后补测。测试对象是观察模块，本轮不评价枪法、走位或“像不像真人”。

## 准备

1. 关闭游戏后安装本次构建。记录测试包中的源码提交和产物 SHA256，避免拿旧版结果作判断。自动构建通过不等于游戏内通过。
2. 使用本地主持的私人多人对局，普通团队死斗（TDM），先选一张熟悉的普通小地图。推荐只有你和一个敌方人机，避免诊断焦点变化；如果界面不允许这种人数，记录实际人数并尽量减少其他参与者。连接数最多 12，包含可能的旁观者。
3. 在脚本管理器中临时禁用 BOTS OVERHAUL（`matchstats.gscc`）和 LUMEN BOTMOD（`lumen_botmod.gscc`），保留 LUMEN 加载环境与其他必要脚本。先保存原设置；本项目的部署工具不会替你切换它们。若不能关闭，仍可做加载和自测，但注明“混合环境”，不要用它评价行为或干净对照。
4. 通过你当前 LUMEN 版本实际提供的命令输入入口或 DVAR 编辑器，在**地图初始化之前**设置以下值，然后重新进入地图：

   ```text
   hbot_probe_enabled 1
   hbot_memory_selftest 1
   hbot_memory_enabled 1
   hbot_debug_enabled 1
   hbot_debug_bot 1
   hbot_debug_human 1
   ```

这里列出的是变量和值，不保证某个版本的输入入口可以直接粘贴整段命令。逐项设置并回读确认；本地入口和键位尚未实测，不猜测按键，也不要假设放一个 CFG 文件就会自动执行。如果找不到输入入口或变量不能生效，先反馈“卡在准备第 4 步”，其余项记为 `not_run`，不要反复开图猜测。

所有开关仅在初始化读取；对局中修改后必须重新开图。诊断默认关闭。`bot#1` / `human#1` 是当前玩家数组中各自第一个参与者，不是玩家姓名或永久编号。多人加入／离开后编号可能变化；数字选择越界会显示 `missing_player`，1–12 以外的配置回退为 1。

可选：用短视频录下提示。不要为本轮测试安装额外驱动或改游戏程序。反馈前遮住玩家名称、聊天、账号和本机路径。

## 提示怎么读

| 提示 | 含义 |
| --- | --- |
| `probe loaded; waiting for match state` | 已进入探针初始化；不能单凭此行认定感知可用 |
| `memory selftest passed=55 failed=0` | 游戏引擎实际执行了当前 55 条原生断言；同时记录 `first_failure` |
| `TDM observer active; behavior_control=0 memory=1` | 模式检查与自测通过，记忆观察已开启 |
| `unsupported: mode=... team=... players=...` | 未进入白名单；把原文反馈回来，不改源码强行放行 |
| `match state timeout` | 等待约 30 秒仍缺少对局状态，观察停止 |
| `sample=visible sample_age_ms=...` | 该目标最近一次采样通过距离、角度和视线检查；不是持续可见保证 |
| `sample=rejected` | 最近采样未通过其中至少一个条件；不单指墙体遮挡 |
| `sample=pending` | 目标尚无采样结果，不能作为遮挡通过证据 |
| `last=(x,y,z) age_ms=... confidence_pct=...` | 只读的最后目击位置（整数显示）、目击年龄与剩余置信度 |
| `[HBOT memory] none` | 当前没有这位目标的有效记忆 |
| `observer_inactive` / `target_inactive` | 观察者／目标死亡、旁观或尚未进入可参与状态 |
| `same_team` / `observer_pending` / `missing_player` | 焦点为友方／观察者尚未建档／所选参与者不存在 |

焦点提示名义上每秒一组，聚合计数每 5 秒一组。它们属于采样快照，可能受引擎显示时长、刷新频率和调度影响。不要把 `sample_age_ms` 当成真人反应时间。如果提示闪得太快、被遮住或完全看不到，反馈这个现象，不要靠猜测填 `pass`。

## A 组：必须先做

| 编号 | 操作 | 通过标准 | 需要反馈 |
| --- | --- | --- | --- |
| A1 | 开启上述变量，进入 TDM 地图，观察开局提示 | 看到自测 `passed=55 failed=0`，随后 `behavior_control=0 memory=1`，无脚本错误／崩溃 | 提示原文或视频；若失败，给出 `first_failure` |
| A2 | 你与唯一人机分到敌方，存活后等待约 10 秒 | 焦点对应 `bot#1 human#1`；不持续卡在 `missing_player`、`same_team` 或 `observer_pending` | 你与人机是否敌对、实际人数、焦点提示 |
| A3 | 在安全的遮挡处待约 30 秒 | 游戏可继续操作，无持续报错／明显新卡顿 | 是否崩溃、报错或提示刷屏；帧率仅作观察，不判定性能达标 |

**A1 失败就停止 B/C 组。** 没看到自测提示不等于自测失败，先记 `not_run` 并反馈缺少哪一行。若收到 `unsupported`，记录实际模式标识、团队标记和人数。A2 不满足时先修正敌我／焦点，不拿后面的输出作结论。

## B 组：感知与记忆

真人玩家和人机都可能移动。使用结实墙体／完整建筑转角，避开玻璃、栏杆、薄板和烟雾。不要依靠旧补丁让人机定住、无敌或改变视角。

| 编号 | 操作 | 通过标准 | 需要反馈 |
| --- | --- | --- | --- |
| B1 | 出现在人机面前的开阔位置，保持足够近；被击杀可重试 | 看到 `sample=visible` 和有效 `last`，连续目击时年龄较低 | 记录一次完整焦点与记忆输出；没见到 visible 时不要继续判定 B2 |
| B2 | B1 成功后立刻绕到实墙后，再沿遮挡移动至少 6 秒；确保敌人没有绕过来重新看见你 | `sample` 变为 `rejected`；失视后 `last` 保持不变、`age_ms` 上升、置信度下降，约 4 秒到期后为 `none` | 最好录下从 visible 到 rejected 再到 none 的连续片段；提示每秒刷新，可允许约一轮显示延迟 |
| B3 | B2 到期后重新回到人机面前 | 新的 visible 样本重新建立记忆，坐标对应新的目击点 | 重新出现前后的提示 |
| B4 | 再做一次 B1→B2 | 第二次仍能正常记住／遗忘，无旧记忆长时间残留 | 是否能重复；目标或观察者在此期间是否死亡 |

B2 只有在持续 rejected、目标保持存活且没有重新暴露的情况下才有意义。如果人机移动到能看见你的地方，样本恢复 visible、记忆刷新是正常的；标注“重新暴露，需重试”。如果你或人机死亡中断，记录“中断”，不要算遮挡通过。`rejected + none` 从头出现但未先观察到 visible，也不能证明记忆过期正确。

当前不是完整的人类视觉：只检测胸部附近单点，不处理完整烟雾语义、声音和多身体点；不把这类边界列为本轮必须通过项。坐标来自记忆，不显示隐藏目标的实时坐标。

## C 组：生命周期与退出

| 编号 | 操作 | 通过标准 | 需要反馈 |
| --- | --- | --- | --- |
| C1 | 人机已有你的记忆时击杀它；在它重生前后保持遮挡 | 死亡时为 `observer_inactive`；重生后未再次目击前不沿用旧记忆，后续仍可重新发现 | 死亡／重生片段；若重生立即看到你，记“无法判断，需重试” |
| C2 | 结束比赛，再开一局 TDM | 新地图重新自测；没有累积的重复提示或上一局记忆 | 新局开头的输出、是否重复刷屏 |
| C3 | 开关保持开启，另开普通自由混战等非 TDM 模式 | 显示 unsupported，无 active／持续 focus 提示；游戏其他逻辑正常 | 模式名称、拒绝提示原文 |
| C4 | 地图初始化前将 probe、selftest、memory、debug 四个开关设为 0，重开地图 | 本项目没有 HBOT 观察输出 | 关闭后的结果 |

换队、加入／离开和超过 12 连接的拒绝测试后续单独补测；本次未实际执行的项目始终保留 `not_run`。C1 验证的是**观察者**生命周期，不代表已实现目标死亡后的所有决策语义。
