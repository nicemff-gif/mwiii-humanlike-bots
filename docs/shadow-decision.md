# TDM 反应与搜索：决策观察原型

本轮交付的是“根据已知信息打算做什么”。诊断可以显示意图；游戏内机器人仍由现有逻辑行动，意图未送入移动、射击或视角控制。

## 状态与输入

| 状态 | 意图 | 进入条件 | 提供坐标 |
| --- | --- | --- | --- |
| idle | none | 无已确认目标、反应中断或搜索结束 | 无 |
| reacting | wait | 当前正样本与记忆目击时间一致 | 无 |
| tracking | observe | 反应等待结束后，另一次正样本确认 | 最近目击快照 |
| searching | search | tracking 收到负样本，或正样本过久未更新 | 最近目击快照 |

单纯时间到达不会把 reacting 变成 tracking；“记忆里有某人”也不会启动新确认。正在反应的目标出现负样本时回到 idle，不把一闪而过的目标直接变成搜索任务。搜索中重新发现、切换目标、样本中断后恢复、记忆期限后恢复，都重新开始反应。

采样元数据只含数字目标编号、正／负结果和显式时间。正样本还必须能在记忆中找到**同一时刻**的可见记录；过时／不一致的正样本不能推进确认。负样本不携带位置。诊断仍仅显示记忆坐标，不向决策提供隐藏目标的实时坐标。

每个观察者有独立控制器。已建立目标且未失效时保持焦点，避免在两个可见敌人间每帧跳转；进入搜索后可以对新的可见目标重新确认。同批目标以较小编号作为稳定次序，尚无距离、威胁或团队目标权重。

## 初始参数与调度

| 参数 | 缺省值 | 有效范围 |
| --- | --- | --- |
| reaction_ms | 250 毫秒 | 1–2000 的整数 |
| search_ms | 3000 毫秒 | 1–10000 的整数 |
| stale_ms | 2000 毫秒 | 1–5000 的整数 |

无效参数回退至缺省值。这些数值是待校准的工程初值，不是实测真人反应分布。搜索期限还受默认 4000 毫秒的记忆期限限制。没有持续正样本时，最迟在样本陈旧期限进入搜索；任何搜索都不能越过记忆过期。

同一批采样至多两个候选，保持原有射线预算；观察调度每轮为所有活动记录推进决策时间，然后消耗该批事件。没有额外射线。GSC 调度和帧耗时尚未测量，不能把名义 0.05 秒轮间等待视为精确运行频率，也不能把本阶段 tracking 当作开火许可。

观察者死亡和清理时，记忆与决策一同重置；重生重新建档。对局退出直接移除自己的观察记录。时间倒退、无效时间也清空本控制器和其记忆。目标死亡、重生身份与完整模式事件的运行语义尚未验收。

## 自动验证与待测项

`tests/fixtures/decision_scenarios.json` 有 15 个场景、126 条原生断言，涵盖反应边界、短暂目击、失视搜索、精确过期、重新确认、样本陈旧、稳定焦点、未确认记忆、重置、时间倒退、无效时间、过时证据和配置边界。

Python 参考模型实际运行场景；另以固定种子的 1000 个采样批次检查顺序无关性、反应约束、搜索期限和坐标来源。生成器从同一场景输出原生断言，调用实际 `hbot_decision` 与 `hbot_memory` 模块；这些断言已包含在构建中，**尚未在引擎执行**。Python 对非法类型的约束可能比引擎严格，场景通过不等于覆盖所有 GSC 动态类型。

普通包仍默认关闭；明确选择的 `manual-test` 包开启现有观察、自测和诊断。本轮自测会先显示原有 `memory selftest passed=55 failed=0`，再显示 `decision selftest passed=126 failed=0`，任何失败都会停止观察。

焦点输出新增：

```text
[HBOT plan] state=searching kind=search focused=1 reaction_ms=0 search_ms=...
```

`focused=1` 表示该观察者意图的目标与所选真人一致；为 0 时不能把所选真人的记忆行当作当前意图目标。`reaction_ms` / `search_ms` 是剩余预算，不是实测时延；诊断约每秒刷新，250 毫秒的 reacting 可能完全没出现在输出里，不能据此认定跳过了等待。

人工测试可按用户时间延期，所有游戏内结果保持 `not_run`。有空时按 [测试文档](manual-test-01.md) 执行，新增的 D 组只适用于包含决策模块的构建；旧的已安装包没有这项提示。
