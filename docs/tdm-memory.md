# TDM 有限感知与记忆：观察原型

## 当前范围

此版本只观察和记录，不接管移动、瞄准、射击、武器或伤害。它为后续搜索决策提供受约束的记忆输入；当前不会让原版或旧补丁控制的人机开始按这份记忆行动。

首轮白名单为内部模式标识 `war`、`level.teambased` 为真、`level.players.size` 在 1–12 之间。人数按引擎连接数组保守计算，可能包括旁观者。未知模式、缺失状态或人数越界会停止自己的观察任务，不尝试修改模式。

`war` 的选取依据是 [公开 TDM 脚本结构](https://github.com/ate47/mwiii-source/blob/main/mp/scripts/mp/gametypes/war.gsc) 中的 TDM 出生点和团队计分逻辑。该资料为第三方转储，本地 1.21 的实际返回值仍需实测；不自动猜测 `tdm`、硬核等别名。

## 模块边界

- `mode.gsc`：纯模式白名单。
- `perception.gsc`：唯一接触观察者和候选实体的适配器，检查存活、队伍、距离、视角和引擎射线。
- `memory.gsc`：只接收目标编号、已观察位置和显式时间，不访问引擎实体、全局玩家数组或实时世界坐标。
- `probe.gsc`：初始化、调度、生命周期和聚合诊断。

候选实体的世界位置只用于适配器构造距离／视线查询。检查不通过时返回 `undefined`，不会把隐藏位置传给记忆。当前视线检查只取胸部附近单点，加 1800 游戏单位距离、水平半角 60 度和垂直半角 45 度限制。它不是完整的人类感知模型，未加入声音、烟雾语义、反应时间和多身体点可见性。

每个观察者最多保留 16 条记忆，默认 4000 毫秒失效。再次目击更新位置和期限；失视只让时间推进，不更新位置。置信度随记忆年龄线性降低，精确到期即移除。容量满时淘汰最旧目击记录。时间倒退、无效时间、观察者死亡或重新建档时清空旧记忆。

轮转调度每轮只扫描一个观察者，最多采样两个敌方候选；轮间等待 0.05 秒，限制为名义最多每秒 40 次射线查询。实际节奏取决于 GSC 调度，尚未做性能实测。目标轮转、有限采样和单点视线均可能造成漏检；此阶段不以命中率或发现速度衡量成功。

## 两层场景验证

`tests/fixtures/memory_scenarios.json` 定义 12 个记忆场景和 12 个模式边界。覆盖从未见过、隐藏移动、刷新、过期、容量淘汰、时间倒退、死亡清空及无效输入。

Python 参考模型在 CI 中运行这些场景；构建器从同一份场景生成 GSC 原生自测，并与实际 GSC 记忆模块打包。原生自测只能在游戏内执行，编译通过不表示这些断言已在引擎中通过。参考模型还对无效／非有限输入更严格，不能据此宣称引擎处理了所有非法数值。

## 游戏内步骤与预期

先选择无两个旧人机补丁的对照配置，并记录实际启用脚本；当前工具不会自动关闭第三方脚本。

在地图初始化前设置：

```text
hbot_probe_enabled 1
hbot_memory_selftest 1
hbot_memory_enabled 1
```

三个变量默认均为 0，仅在本次初始化读取。启用记忆时会先运行原生自测，即使未单独打开 selftest 开关；任何断言失败都会停止观察。HUD 给出通过／失败数量与第一个失败场景，未知模式则显示不支持并退出。

在固定 TDM 地图中检查：

1. 原生自测 `failed=0`，记录当前源码提交和产物摘要。
2. 人机视角范围内出现敌人后，自己的观察记录产生最后目击位置。
3. 玩家进入遮挡后继续移动，记录位置保持不变，置信度下降并在期限后失效。
4. 观察者死亡、重生、换队或离开后，不沿用上一份实体生命周期的记忆。
5. 结束比赛后任务结束，重新开图没有旧记录；其他模式无观察任务。

当前只输出聚合计数，逐目标游戏内检查仍需后续诊断视图或调试观测支持。此前安装的旧补丁若仍启用，会继续控制人机行为，不能据此评价新记忆策略的战斗表现。

所有原生场景、地图加载、生命周期和行为实测目前均为 `not_run`。后续动作仲裁和搜索决策在这些边界验证后接入。
